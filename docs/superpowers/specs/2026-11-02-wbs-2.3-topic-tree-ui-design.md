# WBS 2.3: Topic Tree UI (Cây chủ đề & Tiến độ môn học) — Design Document

## 1. Intent & Overview
In the SFSH academic workflow, students break down course syllabi into sequential topics/chapters to track comprehension and prioritize upcoming study sprints.
**WBS 2.3** replaces the temporary `PlaceholderPage` at `/syllabus` with a dedicated, interactive **Topic Tree & Mastery Progress UI**.

### Acceptance Criteria (from Project Master v4)
> **WBS 2.3:** "Switching `TODO`/`DOING`/`DONE` updates the progress bar immediately and rolls back if the API fails."

---

## 2. Goals, Non-Goals & Anti-Goals

### Goals
- **Course Selection:** Top navigation tabs + responsive dropdown selector to switch between enrolled courses (`CS101`, `MATH201`, `PHY110`, `ENG102`...).
- **Course Mastery Card:** Real-time visual progress indicator (Mastery Percentage, breakdown of `DONE`, `DOING`, `TODO` counts, and completion status).
- **Hierarchical Topic Tree:** Sequential chapter cards (`Chapter 01`, `Chapter 02`...) with titles, descriptions, and interactive status chips.
- **Optimistic UI with Rollback:** State and progress bars update instantly (<16ms) upon clicking `TODO` / `DOING` / `DONE`. If the API request fails, state rolls back to the prior value with a toast alert.
- **Manual Chapter Add/Edit:** Allow students to manually add or edit chapter titles and descriptions.
- **Design System & Performance:** 100% compliant with Luma Green theme (`#243100`, `#DBEF90`, Urbanist typography), dark/light mode, full EN/VI bilingual support, and GPU-safe 60 FPS GSAP animations.

### Non-Goals
- Automated Gemini PDF syllabus ingestion (this is **WBS 2.2**, assigned to backend developer Giang).
- Automatic task deadline creation from topics (handled in **WBS 2.4b**).

### Anti-Goals
- Blocking the UI with full-page loading spinners when changing a single topic's status.
- Discarding optimistic updates when a network glitch occurs without notifying the student.
- Hardcoding course topics without fallback support when Giang's backend API is still in development.

---

## 3. Approaches Considered & Selected Approach

### Approach A: Standalone Accordion Cards per Course
- *Concept:* Render every course as an expandable accordion on a single long scrolling page.
- *Trade-off:* Becomes cluttered and overwhelming when students take 5–7 courses with 10+ chapters each.

### Approach B: Horizontal Tabs / Dropdown + Vertical Topic Tree with Mastery Header (Selected)
- *Concept:* 
  - Sticky top course selector bar with quick completion badges.
  - Mastery Summary Card showing current course progress, grade forecast, and topic distribution.
  - Clean vertical list/tree of chapters with 3-state radio pills (`TODO`, `DOING`, `DONE`).
- *Rationale:* User specifically selected this layout. It provides a focused, single-course study experience without visual noise, matches modern productivity apps (Linear, Notion, Duolingo), and fits mobile screens seamlessly.

## 4. Technical Architecture

### 4.1 Component Breakdown
```
client/src/
├── pages/
│   └── SyllabusPage.jsx                 # Main view route for /syllabus
├── components/
│   └── syllabus/
│       ├── CourseTabs.jsx               # Horizontal course pill tabs + mobile select
│       ├── MasteryHeaderCard.jsx        # Visual progress bar & topic metrics
│       ├── TopicCard.jsx                # Individual chapter card with TODO/DOING/DONE toggle
│       ├── AddTopicModal.jsx            # Modal to add a manual syllabus topic
│       └── ToastNotification.jsx        # Lightweight rollback alert
└── lib/
    └── api.js                           # Extended with getTopics, updateTopicStatus, createTopic
```

### 4.2 Data Model & Contract
Matches Prisma `Topic` schema:
```typescript
interface Topic {
  id: number;
  courseId: number;
  sortOrder: number;
  title: string;
  description: string | null;
  status: 'TODO' | 'DOING' | 'DONE';
}
```

### 4.3 Optimistic Update & Rollback Workflow
1. User clicks `DOING` on Chapter 02.
2. `SyllabusPage` immediately mutates local React state (`prevTopics` cloned and saved in ref).
3. Mastery percentage recalculates and GSAP animates progress bar smoothly to the new percentage.
4. Asynchronous `PATCH /api/topics/:id` is dispatched.
5. **Success:** Local state remains confirmed.
6. **Failure (Network / Server Error):** Local state reverts to `prevTopics`, progress bar rolls back to previous width, and an accessible error notification appears: *"Unable to update topic. Changes rolled back."*

### 4.4 Graceful Fallback Strategy
To enable seamless development while Giang finalizes WBS 2.2:
- `api.getTopics(courseId)` queries `GET /api/courses/:id/topics`.
- If the endpoint returns 404 or connection error, the client seamlessly falls back to pre-seeded curriculum data (from `prisma/seed.js`), persisting local changes in session storage so the user can fully test all interactions.

## 5. Animation & GSAP Specifications
- **GSAP Scope:** Wrapped with `@gsap/react` `useGSAP(() => {}, { scope: containerRef, dependencies: [activeCourseId] })`.
- **Card Entrance:** `.fromTo('.topic-card', { opacity: 0, y: 14 }, { opacity: 1, y: 0, stagger: 0.04, duration: 0.35, ease: 'power2.out', clearProps: 'all' })`.
- **Progress Bar Fill:** Animated via `gsap.to('.mastery-progress-fill', { width: `${percentage}%`, duration: 0.5, ease: 'power1.out' })`.
- **Compositor Clean:** Zero `backdrop-filter` inside dynamic list items to guarantee 60 FPS performance.
